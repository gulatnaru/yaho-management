## Problem

기존 C5는 CONFIRMED 신청 이력이 있는 Child만 대상으로 한다. 등록·예약·입금·동의 기록이 있다는 사실만으로 그 범위에 편입할 수 없다. 제외된 집단에는 출처·목적 종료·고지 근거가 불명확하거나 서로 다른 목적이 섞일 수 있다. 운영자는 각 집단의 독립 보관 근거와 종료 조건을 결정해야 하며, 이름이나 전화번호로 신청자와 Child를 합쳐 그 빈틈을 채울 수 없다.

## Current Process

- **C0/C5:** [ADR-058](DECISIONS.md#adr-058-5년-파기-대상을-phase-18-확정-신청-이력이-있는-아이로-좁히고-파기와-쓰기-경로를-child-행-잠금으로-직렬화한다)은 CONFIRMED `ReservationApplication.childId`가 있는 Child만 C5 대상으로 한정한다. [CTE:62](../lib/reservation-applications/last-reserved-class.ts#L62)와 [현행 scan:166](../server/reservation-applications/retention.ts#L166)도 이 경계를 유지한다. G1–G4에는 이 5년 규칙이 자동 적용되지 않는다.
- **신청 사본 A1:** 수업일(KST)+1년의 만료일 다음 날부터 REJECTED/CANCELLED 사본만 ADMIN 수동 파기 대상이다. SUBMITTED는 만료 목록에 표시해도 먼저 반려·취소해야 한다([계산:56](../lib/reservation-applications/retention.ts#L56), [상태 제한:86](../lib/reservation-applications/retention.ts#L86), [목록 분리:138](../server/reservation-applications/retention.ts#L138)). 이 기존 운영기간의 법적 적합성까지 새로 검증된 것은 아니다.
- **신청과 Child:** 제출은 Submission/ReservationApplication을 만들며 Child/Reservation을 생성하지 않는다([제출:298](../server/reservation-applications/groups.ts#L298), [신청 생성:325](../server/reservation-applications/groups.ts#L325), [ADR-053:480](DECISIONS.md#L480)). `requestedChildId`는 기존 Child 선택 의사이고 확정 연결 `childId`와 다르다([schema:542](../prisma/schema.prisma#L542), [schema:569](../prisma/schema.prisma#L569)). 새 Child 생성은 확정 경로에 있다([finance:329](../server/reservation-applications/finance.ts#L329)).
- **현행 제거 단위:** C5는 Child 제자리 변환, Consent/Safety/Relationship 및 해당 DeviceChild 삭제, 예약 자유입력 NULL, 확정 신청 사본 파기와 요청 연결 tombstone을 처리한다([retention:342](../server/reservation-applications/retention.ts#L342)). S는 모든 자녀 신청이 파기된 Submission의 보호자·선언명·Deposit.payerName·Return.reason을 지운다([retention:223](../server/reservation-applications/retention.ts#L223)). S에는 별도 미반환 잔액·증빙기간 검사가 없다. Payment.payerName/memo·Refund.reasonDetail은 일반 Child 파기에서 보존된다. 이 현행 동작을 새 집단의 승인 근거로 전용하지 않는다.

## User Story

운영자는 확정 이력이 없는 아이와 신청자의 개인정보를 실제 목적별로 정리하면서, 진행 업무·미정산·필수 증빙·다른 가족의 유효 목적을 훼손하지 않는 결정 기준을 갖고 싶다.

## Scope

G1 / D17-ADMIN, G2 / D17-HISTORY, G3 / D17-UNCONFIRMED, G4 / D17-MIXED의 ①–⑧ 결정표, 집단별 파기 자격·사전 확인 조건, 목적별 종료 후보와 독립 승인 질문을 작성한다. G4는 G1–G3에 겹치는 overlay이며 별도 인원 집단으로 합산하지 않는다.

## Out of Scope

이 파일 외 수정, REQUIREMENTS/ADR 반영, 최종 정책·설계 승인, 구현·테스트·CI·빌드, stage/commit/push, 모든 DB 접근·실제 개인정보 조회·삭제, migration·scheduler. 금액·환불 정책·수집항목·신규 개인정보/hash 저장을 결정하지 않는다. Round 5 충돌 통합은 마지막에 목록만 남긴다.

## Business Rules

- **집단별 독립 결정:** G1·G2·G3·G4 모두 기존 CONFIRMED 5년 규칙을 상속하지 않는다. 각 D17 행의 근거·필드 범위·종료 사건·기간·기산점·예외를 운영자가 별도로 결정해야 한다. C5를 쓰는 helper나 CONFIRMED CTE의 필터를 넓혀 대신하지 않는다.
- **A층/B층:** A층은 예약·출결·금융행, FK·금액·일시·상태·사유 enum·처리 책임·배정·환불/반환 누계다. B층은 이름·연락처·메모·건강정보 등 개별 개인정보의 목적별 필요성이다. A층 보존을 모든 B층 장기보관의 근거로 삼지 않는다. `L`은 실제 적용 증빙 분류의 기간·기산점으로 **ESTIMATE / 미결정**이다. 원장 자체의 최종 폐기는 이번 결정 범위 밖이다.
- **처리 코드:** SPEC의 `N`은 승인된 nullable 개인정보 필드 NULL/자유입력 제거, `C`는 Child를 삭제하지 않는 기존 제자리 변환(공통 이름 표식·신원/연락/메모 제거·비활성·파기 표시), `D`는 승인된 해당 부속행 삭제다. 이 방법을 재사용할 수 있다는 사실이 새 집단의 기간·파기 자격·동의 삭제 예외를 승인하지 않는다.
- **추천의 상태:** 아래 ③은 목적 종료 사건 후보이며 법정 기산점 확정값이 아니다. 신규 기간·법령 적용·증빙 예외·hold는 모두 **ESTIMATE / 미결정**이다. SPEC에 없는 숫자 기간을 추가하지 않는다. A1/C5의 기존 승인 사실과 A17의 미승인 제안을 구별한다. 등록일·수정일·예약일·입금일에 임의 기간을 더하지 않는다.
- **법령 코드:** P는 개인정보 보호법의 수집·이용/목적 종료·파기/민감정보 검토, H는 아동·법정대리인·건강정보 검토, E/T/C는 전자상거래·세무·상업장부 증빙 후보다. 목적·고지와 보존 예외를 구별하는 공식 [제15조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033214947)·[제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334901), 별도 검토가 필요한 [제22조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020398523)·[제23조](https://www.law.go.kr/lsLinkCommonInfo.do?ancYnChk=&chrClsCd=010202&lsJoLnkSeq=1020398539)를 보조 확인했다. E/T/C의 공식 [전자상거래법 제6조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031806293)·[시행령 제6조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lspttninfSeq=63460)·[국세기본법 제85조의3](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1008304643)·[상법 제33조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900396083)도 조문 후보만 확인했다. **YAHO의 개별 적용·필수 개인정보 범위·기간·정확한 기산점은 검증되지 않았다.** 법령의 숫자를 고객 전체 기간으로 채택하거나 전자금융업자의 의무를 자동 적용하지 않는다.
- **정체성과 분류:** C0 여부는 입증된 Child 연결로 판단한다. 신청만 있는 사람은 Child가 없을 수 있다. 보호자·신청에 적힌 아동·기존 Child를 같은 대상이라고 자동 단정하지 않으며 전화번호 일치로 병합·출처 추정·접근 복구하지 않는다. G1/G2는 연결 신청 부재까지 확인하는 개념적 범위다. `requestedChildId` 등 신청 연결이 있으면 G3 관계를 별도 검토하며, 연락처로 누락 관계를 만들어내지 않는다. CONFIRMED가 새로 확인되면 해당 Child는 C0로 분리하고 A17 판정을 중단한다. 연결 관계가 불명확하면 분류 미확정으로 남긴다.
- **부분 처리와 권한:** 만료한 필드·목적만 다루고 살아 있는 목적의 최소 필드·다른 형제/가족·공유 Payment·공용 본문을 보호한다. 부분 안전정보 파기를 Child 전체 `personalDataPurgedAt`으로 표시하지 않는다([PLAN Data Model](ITERATION-6E-PLAN.md#data-model)). 기존 ADMIN 관리·재무 경계, 안전정보 목록 제외·상세 접근, 동의 append-only를 유지하며 새 역할을 발명하지 않는다.
- **사본·잔존 연결:** SPEC B1–B4와 R1–R3의 방향 후보를 참조한다. 잔존 ID/FK·형제·기기·공용 본문·외부 장부는 재식별 단서가 될 수 있다. 필드 NULL/공통 표시를 법률상 익명정보나 백업까지 파기 완료로 단정하지 않는다. 원문·이름/전화 hash·역매핑을 새로 보관하지 않는다. 고객 파기로 User/ADMIN 계정을 연쇄 삭제하지 않는다.

| **G3** | 사본은 **REJECTED/CANCELLED + 기존 A1 만료**가 기본 자격; SUBMITTED는 종결 전 부적격. 독립 Child는 별도 D17 근거·기간이 있어야 하며 사본 만료로 함께 처리 불가. S는 모든 형제 신청 파기 조건을 별도로 만족해야 함. | **미종결 신청·진행/미래 예약·CONFIRMED 연결·미정산/미반환·실제 분쟁·법정 증빙**을 사본/parent/Child/거래별 확인. 유효 형제가 있으면 parent 조기 파기 금지. 모든 형제가 파기되어도 현행 S의 미반환 검사 부재가 해소되는 것은 아님. 충돌은 R1 의존 미결정으로 남김. 요청 Child의 신원/권한·tombstone·최소 반환 연락·기기/완료 접근 영향도 별도 확인. |
| **G4** | 해당 G1–G3 범위에서 **목적·필드마다 승인된 기간/종료 조건 충족**, 필요한 최소 범위/hold 분리와 부분 처리 단위 확인. Child 전체 변환은 해당 Child 신원·부속행의 모든 잔존 목적/예외 종료와 실행 조건을 확인한 경우만 후보. | 각 목적에서 **진행/미래 예약·미종결 신청·미정산/미반환·실제 분쟁·법정 증빙**을 확인. 미해결금·분쟁이 있으면 그 업무에 필요한 승인 필드만 hold 후보; 다른 모든 PII 연장 금지. 유효 현장 안전·동의 입증·형제/다른 가족/공유 원장·공용 본문을 확인하고 C0가 새로 성립하면 A17에서 제외. 필드별 종료가 불명확하면 해당 범위 보류. |

**네 집단 모두의 공통 사전 확인:** 담당 운영자는 대상 Entity/FK와 출처의 확실성, 실제 고지·동의/계약·현재 목적, 승인된 사건 증거·기간·기산점·만료 경계, 미해결금·살아 있는 예약/신청·실제 분쟁·필수 증빙, 제거 필드·남는 원장·형제/공용 영향과 접근자를 확인해야 한다. 예외/hold에는 사유·근거·최소 필드·해제 사건·재검토일·담당자와 최종 잔존 조건을 정해야 하며 포괄 무기한 hold는 승인 후보가 아니다. 필요한 사실이 없으면 추측·날짜 backfill 없이 미결정으로 남긴다. 향후 실행에는 PLAN의 잠금 후 재판정·명시 승인 scope·ADMIN 권한 및 사본/백업 최종 잔존·복구 후 재파기 책임/증거 확인도 필요하다. **이 문서는 그 사실을 조회하거나 조건 충족을 확인한 실적이 아니다.**

### G1 보충 — 출처 미상을 관리자 등록으로 바꾸지 않는 결정

[Child schema:222](../prisma/schema.prisma#L222)에는 `registrationSource`·등록 처리자·마지막 연락·목적 종료 컬럼이 없다. 관리 화면의 생성 경로가 존재해도 그 경로는 출처를 기록하지 않는다. 신청·예약 부재는 **현재 연결 이력의 부재**이며 과거 등록 경위의 증명이 아니다. `registeredAt/createdAt/updatedAt`·이름·전화번호·메모 형태를 근거로 관리자 등록이라고 복원하지 않는다.

따라서 D17-ADMIN은 관리자가 등록했다고 입증된 경우와 **출처 미상·신청/예약 없음**인 경우를 구별해 답해야 한다. 후자도 실제 목적 종료·적법 근거·과거 고지 처리의 확인을 거쳐 정리할 수 있는 방향을 선택할지, 근거 확보가 가능한 범위부터 순차 판단할지 미결정이다. “미상”은 이번 검토의 상태 표현이며 신규 저장 필드·증빙 사본 수집·과거 출처 backfill의 설계가 아니다. 근거를 확인하지 못한 대상은 제한 접근과 재검토 책임을 정해야 하며, 미상이라는 이유만으로 즉시 파기 또는 무기한 보관을 확정하지 않는다.

### G2 보충 — 마지막 수업 사실과 C5의 자격은 다르다

[유효 예약 helper:6](../lib/reservation-applications/last-reserved-class.ts#L6)은 C5에서 NO_SHOW·출결 후 취소를 포함하고 수업 전 취소·취소 클래스를 제외하며 예정 예약도 계산한다. 이는 **CONFIRMED 고객의 기존 계산 규칙**이다. G2의 마지막 실제 수업 제공, NO_SHOW의 제공 기회 종료, 취소 통지·정산·문의 종결을 같은 사건으로 증명하지 않는다. 참석하지 않은 예약을 실제 참석으로 간주하거나, `attendanceRecordedAt`을 수업일로 대체하거나, 과거 RESERVED를 종결 완료라고 단정할 수 없다. 취소 종결이 일자 필드로 없으면 `cancelledAt/endsAt/updatedAt`으로 추정하지 않는다.

기간이 같아 보이는 거래 법령 후보와 C5도 근거가 다르다. **CONFIRMED 이력이 없고 당시 고지·동의가 확인되지 않은 집단에, 날짜 helper를 재사용한다는 이유로 C5 5년을 가져올 수 없다.** 당시 수업·취소/대사의 필요 범위와 기간을 D17-HISTORY로 독립 결정해야 한다. 새 예약은 새로 살아난 목적의 필요 필드만 다시 검토하는 후보이며, 과거 건강정보·메모 전체를 자동 갱신하는 정책이 아니다.

### G3 보충 — 사본·미종결 신청·독립 Child·반환 연락

- **REJECTED/CANCELLED 사본:** 기존 A1의 수업일(KST)+1년·만료일 다음 날·수동 실행을 유지한다. 반려/취소 후 별도 기간을 새로 시작하지 않는다. 원문 제거 범위는 아이·보호자·관계·요청사항·resolutionNote이며 신청 행·상태·처리 시각/actor·확인/동의 boolean/version은 남는다([retention:210](../server/reservation-applications/retention.ts#L210), [파기:311](../server/reservation-applications/retention.ts#L311)). 이것이 동의 증빙 전체의 최종 보존기간 확정이나 다른 개인정보 사본의 종료를 뜻하지 않는다.
- **SUBMITTED:** 수업일 기준 기간이 지나도 `expiredPending`이며 파기 부적격이다. 클래스가 취소되거나 날짜가 지났다는 이유만으로 자동 반려/취소하지 않는다. ADMIN의 수동 종결 책임·종결 근거·연락 처리와 업무 기한은 별도 결정 사항이다. 종결 전 파기 금지는 무기한 미처리를 승인하는 뜻이 아니며 새 기한 숫자를 임의로 만들지 않는다.
- **독립 Child:** 신청 제출만으로 Child가 생기지 않는다. `requestedChildId`는 선택 요청일 뿐이고 전화번호가 같아도 별도 Child를 사본과 함께 지울 수 없다. 입증된 연결과 Child 자체의 목적·과거 예약 사실·G4 부속 목적을 따로 확인한다. 그 Child에 과거 CONFIRMED 이력이 있으면 **Child는 C0**, 현재 미확정 사본은 별도 A1 상태 조건으로 판단한다. Child에 CONFIRMED가 없으면 C5 밖이며 D17의 새 승인 근거가 필요하다. 신청 사본의 종결·파기 자격으로 Child 신원이나 기존 동의이력을 덮어쓰지 않는다.
- **미반환:** ReturnObligation의 amount/returnedAmount/resolvedAt, 실제 Return·입금/배정과 미배정 가용액 등 원장 사실을 구별한다([schema:712](../prisma/schema.prisma#L712), [ADR-060:549](DECISIONS.md#L549)). 신청 종결이 곧 반환 완료는 아니다. 필요한 연락의 후보는 입증된 연락 대상의 보호자 이름·연락처 중 반환 연락에 꼭 필요한 필드뿐이며, 둘 다 필수라고 확정하지 않는다. 은행계좌·새 연락자 등 수집항목을 추가하지 않고 아동 생년월일·성별·요청사항·안전정보까지 묶어 보관하지 않는다. 실제 입금자명·반환 사유는 연락처가 아니라 R1의 독립 거래 PII 결정 대상이다.
- **S와 후속 접근:** 미파기 형제가 있으면 parent를 조기 파기하지 않는다. 모두 파기되어 S가 성립해도 미반환 목적·별도 법정 증빙과 충돌할 가능성은 R1의 미결정이다. 이를 해결하려고 기존 A1/S를 자동 연장·단축하거나 전체 원문을 새 보관소에 복제하지 않는다. R3의 기기/완료 capability 종료와 파기 후 read-only receipt·write-replay 종료도 독립 승인 전제이며, 현행 구현 완료로 취급하지 않는다.

### G4 보충 — 목적별 종료·필드·기간의 독립 결정

아래 네 행은 D17-MIXED 안에서도 따로 답해야 한다. 모두 **ESTIMATE / 미결정**이며 G1–G3의 자격·사전 확인 위에 겹쳐 적용할 방향 후보다.

| 목적 | 필요 범위와 분리 | 추천 종료 사건·기산 후보 | 기간 검증·파기 전 예외 확인 |
| --- | --- | --- | --- |
| **예약 이행** | 해당 수업 참가자 확인·보호자 연락에 필요한 Child/예약 PII. 구조적 예약·출결 이력과 분리. | 실제 제공 완료 또는 취소 통지·정산·해당 문의 종결. 신청만이면 G3의 수동 종결 조건 별도. | 기간·기산점 **미결정**. 진행/미래 예약·미종결 신청·필요 연락이 남으면 해당 최소 필드의 종료를 확인. 과거 예약이 있다는 이유의 C5 상속 금지. |
| **거래 증빙** | 원장/FK·금액/누계·일시/상태 보존과 실명·메모·사유를 분리. R1의 각 필드·R3의 연결/키 판단에 의존. | 대사·환불/반환 이행·실제 분쟁 종결 및 **실제 적용 증빙의 기산·종료 사건**을 각각 확인. | L 및 원문 필요기간 **미결정**. 미정산/미반환·실제 분쟁·필수 증빙의 필요한 필드/접근자/해제일만 검토. paidAt을 세무 신고기한·장부 폐쇄일로 치환하거나 금융 최장기간으로 다른 목적을 연장하지 않음. |
| **동의 입증** | 동의 유형·action·version·recordedAt·출처/최소 연결 중 입증에 필요한 범위를 검토. 동의 증빙 필요성이 건강 원문·전체 연락처의 필요성을 뜻하지 않음. | 해당 동의로 수행하던 이용 목적 종료/철회와, 실제 처리의 적법성을 입증할 필요의 종결을 구별. | 입증 필요기간·기산·예외 **미결정**. `recordedAt`은 동의 기록 시각이며 자동 만료/재동의 시각 아님. 일반 append-only를 유지하고 비CONFIRMED의 삭제 예외는 별도 승인. 과거 consentVersion을 갱신하거나 철회 기록을 지워 현재 동의를 되살리지 않음. |
| **현장 안전** | ChildSafetyInfo의 즉시 대응 정보와 비상연락 중 필요한 범위. 일반 고객·재무 정보와 분리하고 목록 include 금지. 공용 safetyMemo 혼입은 R2 별도 범위. | 해당 현장 대응 필요의 종료; 실제 사고가 있으면 필요한 사고 후속대응/관련 분쟁 종결을 별도 확인. | 민감정보 필요기간·기산·사고 예외 **미결정**. 진행/미래 현장 대응과 필요한 별도 처리 근거·최소 사고 증빙을 확인. Safety.updatedAt·보험/금융기간·동의 증빙기간을 건강 원문 보관기간으로 대체하지 않음. |

**단일 최장기간 금지의 이유:** 금융 증빙이 필요한 동안에도 현장 안전정보는 더 이상 필요하지 않을 수 있고, 연락이 끝나도 최소 동의 증빙의 필요가 따로 남을 수 있다. 모든 PII를 가장 긴 기간에 맞추면 목적·필드별 필요성을 입증하지 못하고 아동·건강정보까지 과잉 잔존시킬 위험이 있다(**ESTIMATE**, E01/E04). 반대로 한 목적의 종료로 모두 지우면 살아 있는 예약·안전·필수 증빙을 훼손한다. 같은 필드에 실제 의무가 중첩되는 판단도 최소 범위와 근거에 대한 전문가 확인 대상이며, 이 문서에서 통합 우선순위를 계산하지 않는다.

G4는 **G1의 독립 동의/안전 목적**, **G2의 예약·대사·부속 목적**, **G3의 신청/반환·독립 Child 목적**에 겹칠 수 있다. G4를 별도 사람 수로 더하지 않고, Child가 없는 G3에는 존재하지 않는 ChildSafetyInfo/ChildConsent를 만들어 적용하지 않는다. CONFIRMED 이력이 입증된 Child는 C0로 분리하고 그 Child의 기존 C5·부속행 처리를 유지한다. G4의 새 목적별 후보를 C0에 소급해 기존 기간을 단축·연장하거나 전역 hold를 삽입하지 않는다.

## Acceptance Criteria

- G1–G4 각각 ①–⑧과 D17 ID, 삭제 자격·미정산/살아 있는 예약/분쟁/법정 증빙 사전 확인, 독립 승인 질문이 있다. 실제 대상·건수·조건 충족은 주장하지 않는다.
- G1 출처 미상은 미상으로 유지하며 G2에 C5를 상속하지 않는다. G3의 A1 사본·미종결 SUBMITTED·독립 Child·미반환 최소 연락을 구별하고 신청자=Child/전화번호 병합을 금지한다.
- G4는 목적별 종료 사건/기간·부분 처리·hold·접근을 나누고 G1–G3와의 중복·C0 분리를 명시한다. 최장기간 하나로 모든 개인정보를 보관하지 않는다.
- 새 기간·법 적용은 ESTIMATE / 미결정이며 새로운 숫자 기간·최종 정책 승인·구현·파기 실적이 없다. 변경은 이 파일 하나뿐이다.

## Conflicts — 유지할 규칙과 SPEC 미정합·모호성

- **유지:** REQUIREMENTS [3.1](../REQUIREMENTS.md#31-기본-규칙)(Child 이력 보존), [20-1.2–1.4](../REQUIREMENTS.md#20-12-아동-안전-정보)(최소 안전정보·분리·동의), [A1/C5 범위·수동 파기:1879](../REQUIREMENTS.md#L1879)·[CONFIRMED 한정:1923](../REQUIREMENTS.md#L1923), [24장:2367](../REQUIREMENTS.md#L2367)·[기존 고객/거래/자동 파기 미결정:2380](../REQUIREMENTS.md#L2380); ADR-006/008/050/053–058/060; ARCHITECTURE 4·6·7장. 기존 C0의 C5·A1·S, 금융 보존식/중복 방지·원장/FK·동의 append-only와 기존 만료 예외를 변경하지 않는다. **A17의 새 삭제 자격·부분 Consent/Safety 종료는 아직 승인된 예외가 아니다.**
- **G1 명칭과 출처 증명의 모호성:** SPEC G1은 **“G1 / 관리자 등록·신청 없는 Child”**라고 부르지만 같은 행에 **“등록 출처 필드 없어 관리자 등록 단정 불가; 예약 있으면 G2”**, 분류 보충에는 **“신청 0·예약 0만으로 관리자 등록 출처를 증명할 수 없다”**고 적었다([SPEC:159](ITERATION-6E-SPEC.md#L159), [SPEC:171](ITERATION-6E-SPEC.md#L171)). 명칭을 출처 판정으로 읽으면 맞지 않는다. 직접 논리 모순으로 단정하지 않되, 출처 미상에 적용할 근거·운영자 결정이 미완성이다. 위 D17-ADMIN은 미상 상태를 보존하는 **새 방향 후보**이며 출처를 확정하거나 SPEC을 고쳐 해소하지 않았다.
- **G3의 A1과 미반환/S 경계 미결정:** SPEC G3의 **“사본 A1 유지”**, **“반환 미완료는 필요한 연락 필드만 검토”**와 BR3 S의 **“Submission의 모든 자녀 신청이 각 A1/C5에 따라 파기된 뒤 parent/Deposit/Return PII 제거”**를 함께 보면, A1/S가 성립했는데 필요한 반환 연락·별도 증빙 목적이 남는 경우의 선후가 정해져 있지 않다([SPEC:161](ITERATION-6E-SPEC.md#L161), [SPEC:84](ITERATION-6E-SPEC.md#L84)). 현행 S에는 미반환 검사도 없다. R1의 미결정을 유지하며 실제 발생을 주장하거나 A1/S를 자동 연장·단축하지 않는다. G3의 **“신청 A1 이미 승인”**도 SUBMITTED까지 파기 가능하다는 뜻으로 읽지 않는다. 같은 행의 **“SUBMITTED는 종결 전 파기 금지”**가 기존 자격 제한이다.
- **G4 부분 처리의 승인 단위 미완성:** SPEC G4의 **“만료 필드/행만 N/C/D; 살아 있는 목적의 최소 필드·원장 보존”**([SPEC:162](ITERATION-6E-SPEC.md#L162))는 방향이나, C/D의 기존 전체 Child 변환·부속행 삭제를 어느 부분 목적에 어떻게 적용할지는 승인된 규칙이 아니다. PLAN은 **“부분 안전정보 파기에 Child 전체 purge marker를 쓰지 않음”**이라고 조건을 둔다([PLAN:46](ITERATION-6E-PLAN.md#L46)). 위 목적표도 최종 삭제 단위·새 append-only 예외를 확정하지 않는다.
- **R2에서 발견한 SPEC 미정합 — 그대로 미해결:** F50–F53/F57의 **“해당 개인정보 목적 종료 후 전체 필드 NULL 제안”**과 **“고객 한 명의 C5로 공용 내용·다른 강사/아이 정보 일괄 제거 금지”**는 개인 목적 종료와 공용 필드 전체 목적 종료가 다를 때 제거 단위를 정하지 못한다. F54는 **“개인정보가 혼입되었다면 해당 내용 제거 제안”**으로 별도 표현한다([SPEC:148](ITERATION-6E-SPEC.md#L148), [R2 Conflicts](ITERATION-6E-DECISION-R2.md#conflicts--유지할-규칙과-spec-미정합)). G4가 혼입 사본·공용 영향을 발견하더라도 이번 라운드가 전체 NULL/부분 제거 중 하나로 조용히 통합하지 않는다.
- **R3의 연결·재시도 미결정 유지:** K01의 **“원장 기간 L과 개인 연결 가능 기간 분리; 별도 종료기간 미정”** 및 **“기존 FK 보존”**, K04의 **“고유 키와 원문 필드 비교 유지”** 및 **“B층 원문 제거 후에도 중복 방지 키 필요; 정확한 보존/재시도 창은 별도 승인”**은 잔존 식별 가능성과 파기 전후 계약의 독립 판단을 남긴다([SPEC:155](ITERATION-6E-SPEC.md#L155), [SPEC:158](ITERATION-6E-SPEC.md#L158), [R3 Conflicts](ITERATION-6E-DECISION-R3.md#conflicts--유지할-규칙과-spec-미정합모호성)). D17 승인으로 잔존 FK의 익명성·capability 저장 종료·receipt/replay 계약이 확정되지 않는다.
