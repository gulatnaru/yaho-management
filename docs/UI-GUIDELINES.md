# UI Guidelines (모바일 우선)

이 문서는 REQUIREMENTS.md 21-1장(UI 설계 원칙)과 docs/DECISIONS.md ADR-013~017을
실제 구현에서 지킬 수 있도록 구체적인 수치로 못박은 설계 가이드다.
원칙 서술은 REQUIREMENTS.md/DECISIONS.md가 우선하며, 이 문서는 "어떻게 구현하는가"만 다룬다.
아이 목록 외 다른 도메인(클래스/예약/매출) 목록 화면을 새로 설계할 때도 이 문서를 기본값으로 따른다.

## 1. 화면 폭 기준값
- 모바일/데스크톱을 가르는 기준 브레이크포인트는 Tailwind 기본값 `md`(768px)로 고정한다.
  - 768px 미만: 모바일 레이아웃.
  - 768px 이상: 데스크톱 레이아웃.
- 근거: Tailwind CSS 기본 브레이크포인트(`sm`=640px, `md`=768px, `lg`=1024px, `xl`=1280px, `2xl`=1536px)에서 새 값을 만들지 않고 그대로 쓴다.
- 목록/검색/네비게이션 컴포넌트는 원칙적으로 이 브레이크포인트 하나로만 분기한다. 추가 분기가 필요하면 이 문서에 사례를 추가하고 이유를 남긴다.

## 2. 네비게이션(드로어)
- 브레이크포인트 `md`(768px)를 기준으로 분기한다.
  - `md` 이상(데스크톱): 상단 가로 네비게이션(`<nav>` + `<Link>` 목록)을 노출한다. 햄버거 버튼과 드로어는 렌더하지 않거나 CSS로 숨긴다.
  - `md` 미만(모바일): 상단 가로 네비게이션을 숨기고, 햄버거 버튼 → 좌측 드로어 방식을 쓴다.
  - 분기는 JS 미디어쿼리가 아니라 Tailwind 반응형 클래스(`hidden md:flex`, `md:hidden`)로 처리해 서버/클라이언트 렌더 불일치를 피한다.
- 근거: REQUIREMENTS.md 21-1.2 원문("좁은 화면에서는 ... 기본으로 한다")이 조건부 표현이며, 이것이 원래 의도임을 ADR-017에서 확정했다(ADR-014의 네비게이션 조항을 정정). 데스크톱에서 매번 드로어를 열어야 하는 것은 개발/운영 효율을 떨어뜨리고, 데스크톱 가로 nav를 유지해도 21-1장의 목표를 해치지 않는다.
- 한 컴포넌트(`NavDrawer`)가 데스크톱 가로 nav와 모바일 햄버거+드로어를 모두 캡슐화한다. 상위 레이아웃은 nav 항목 목록을 한 번만 전달한다.
- **드로어 폭**: `w-72`(288px) 고정.
- **애니메이션**: 좌측에서 우측으로 슬라이드 인/아웃, `transition-transform duration-200 ease-in-out`(약 200ms). 드로어 패널은 항상 마운트하고 `translate-x-0`/`-translate-x-full`로 토글한다. 오버레이는 `transition-opacity duration-200`으로 함께 페이드.
- **열림 트리거**: 모바일(`md` 미만)에서만 보이는 헤더 좌측 상단 햄버거 아이콘 버튼(`lucide-react`의 `Menu`/`X`, 열림 상태에 따라 교체).
- **닫힘 트리거**: (1) 오버레이 클릭, (2) `Escape` 키, (3) 드로어 내부 nav 링크 클릭(페이지 이동과 함께 자연히 닫힘), (4) 브라우저 폭이 `md` 이상으로 넓어지는 순간(자동 닫힘, `matchMedia` 구독).
- **바깥 클릭 닫기 구현**: 전체 화면 오버레이 렌더링 + 오버레이 `onClick`으로 확정한다(ref 기반 바깥 클릭 감지는 쓰지 않는다).
- **배경 스크롤 잠금**: 드로어가 열려 있는 동안 `document.body.style.overflow = "hidden"`, 닫히면 원복.
- **접근성 최소선**: 햄버거 버튼 `aria-expanded`, `aria-controls`, `aria-label`(열림/닫힘 상태에 따라 "메뉴 열기"/"메뉴 닫기"). 드로어 패널 `role="dialog"`, `aria-modal="true"`, `aria-label`. 완전한 포커스 트랩은 구현하지 않는다.

## 3. 목록 화면 — 열 개수 상한
- **모바일(768px 미만)**: 항상 3열 이하.
- **데스크톱(768px 이상)**: 5열을 넘지 않는다. 화면이 넓다고 해서 열을 늘리지 않는다.
- 이 상한은 "몇 열까지 기술적으로 넣을 수 있는가"가 아니라 "식별에 필요한 최소 항목이 몇 개인가"로 정한다(REQUIREMENTS 3.3/ADR-013). 상한은 상한일 뿐, 상한까지 채우는 것이 목표가 아니다.
- 아이 목록은 이름/보호자 연락처/예약일자 3열로 확정했다(ADR-014). 나머지 항목은 상세 화면에서 확인한다.
- 목록에 넣을 열을 고를 때 우선순위: (1) 식별자(이름 등 고유하게 구분되는 항목), (2) 운영자가 목록에서 바로 행동을 취하는 데 필요한 항목(예: 전화 걸기), (3) 그 화면의 핵심 상태/최근성 지표 1개. 그 이상은 상세로 보낸다.
- **카드/테이블 전환 기준**: 열이 3개 이하면 `<table>`을 모바일에서도 그대로 쓴다(카드형 전환 불필요). 열이 4개 이상인 목록을 모바일에 노출해야 하는 경우에만 모바일 전용 카드형 레이아웃 도입을 검토한다 — 단, 열 상한(모바일 3열)을 지키면 이 케이스 자체가 거의 발생하지 않는다.
- 아직 값을 채울 수 없는 열(다른 Phase 의존)은 숫자 0이 아니라 `–`로 표시한다(ADR-012). 소유 Phase가 착수하면 그 Phase의 완료 조건에 실데이터 교체를 포함한다(ADR-015).

## 4. 검색/필터 영역 — 접기 규칙
- **기본 노출 기준**: 선택지가 고정된 목록형 필터(Select, 상태값 등)는 기본 노출한다.
- **접힘 기준**: 자유 입력 텍스트 검색(이름, 연락처 등 사용자가 직접 타이핑하는 조건)은 기본 접힘으로 두고, 트리거를 눌러야 펼쳐진다.
- 실사용으로 뒷받침되지 않는 검색 조건(예: 정확한 날짜를 기억해서 검색하는 패턴)은 애초에 만들지 않는다(16장/ADR-016). "일단 만들어두고 접어서 숨긴다"로 대체하지 않는다 — 접는 것과 안 만드는 것은 다른 결정이다.
- **펼침 트리거 구현**: 네이티브 `<details>/<summary>` 기반 공용 컴포넌트(`components/ui/disclosure.tsx`)를 쓴다. 클라이언트 JS 없이 브라우저 기본 동작으로 펼침/접힘을 처리한다.
- **펼침 트리거 위치**: 필터 영역의 마지막(상태 Select 다음), 제출 버튼 이전.
- **펼침 트리거 라벨 규칙**: 제출 버튼과 같은 라벨("검색")을 쓰지 않는다. 아이콘 + 짧은 텍스트 조합을 쓴다(예: 아이 검색 폼에서는 `lucide-react`의 `SlidersHorizontal` 아이콘 + "검색 조건"). 아이콘만 단독으로 쓰지 않는다 — 관리자 도구 사용자가 적어 아이콘만으로는 의미가 모호할 수 있다.
- **초기 펼침 여부**: 접힘 대상 필드에 이미 값이 들어있는 상태로 페이지가 로드되면(즉 사용자가 이미 그 조건으로 검색한 상태) 기본으로 펼쳐서 보여준다. 값이 없으면 접혀 있다.
- 제출은 항상 GET 폼으로 전체 페이지 이동한다(현재 컨벤션 유지). 접힘 상태 자체를 서버/클라이언트 상태로 별도 저장하지 않는다 — 매 요청마다 위 규칙(값 있으면 펼침)으로 재계산한다.

### 4-1. 검색/필터 폼 반응형 배치
- **모바일(`md` 미만)**: 폼 컨테이너는 `flex flex-col gap-3`로 요소를 세로로 쌓는다. Select, Disclosure, Input 등 각 요소는 `w-full`로 폭 100%를 차지해 "가운데 떠 있는" 느낌이 나지 않게 한다. 제출 버튼도 `w-full`로 전체 폭을 차지한다.
- **데스크톱(`md` 이상)**: `md:flex-row md:items-end`로 가로 배치로 전환하고, 각 요소와 제출 버튼은 `md:w-auto`로 내용에 맞는 자동 폭으로 되돌린다.
- 아이 검색 폼(`child-search-form.tsx`)이 기준 구현이다. 다른 도메인(클래스/예약/매출) 검색 폼도 이 패턴(`flex flex-col gap-3 md:flex-row md:items-end` + 요소별 `w-full md:w-auto`)을 그대로 재사용한다.

## 5. 연락처(tel: 링크)
- 전화번호가 입력되어 있으면 반드시 `tel:` 링크로 표시한다. 값이 없으면 "미입력" 텍스트만 표시하고 링크를 만들지 않는다.
- 포맷팅(하이픈/공백 제거, `tel:` 스킴 부여)은 클라이언트 JS가 아니라 렌더링 시점의 순수 함수(`lib/shared/contact.ts::toTelHref`, 모든 도메인이 공용으로 재사용)로 처리한다.
- 화면에 보이는 텍스트는 사람이 읽기 좋은 원본 형식(하이픈 포함 등)을 유지하고, `href`만 정규화한다.
- 목록과 상세 화면 모두에서 동일한 규칙을 적용한다(아이 도메인에서는 `child-table.tsx`와 `[id]/page.tsx` 둘 다 `toTelHref`를 재사용한다).

## 6. 오버레이/모달 접근성
- 화면 밖으로 이동시키거나 투명하게 만들어 "숨기는" 방식으로 닫는 오버레이/패널(드로어, 향후 만들 모달/다이얼로그 포함)은 `transform`/`opacity` 만으로 숨기지 않는다. 닫힌 상태에서는 반드시 `aria-hidden="true"` 를 패널 자체에 설정하고, 패널 내부의 모든 인터랙티브 요소(링크/버튼/입력)에 `tabIndex={-1}` (또는 동등한 방식)을 적용해 키보드 포커스가 도달하지 않게 한다.
- 이 규칙은 좌측 드로어(`NavDrawer`)뿐 아니라 앞으로 추가될 모든 모달/다이얼로그/사이드 패널에 동일하게 적용한다.
