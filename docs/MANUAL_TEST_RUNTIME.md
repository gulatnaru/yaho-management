# Manual test runtime

Set server-only `MANUAL_TEST_ENABLED=true`, `MANUAL_TEST_MOCK_ORIGIN` to the exact HTTPS origin, and `MANUAL_TEST_DATABASE_URL` to a dedicated runtime-role PostgreSQL URL with exactly `schema=manual_test`. The isolated client always uses that URL; invalid configuration and database errors fail closed. Vercel production is always denied. Only `NODE_ENV=test` may omit the URL and use the in-memory adapter.

The existing `prisma/manual-test/migration.sql` bootstrap and the additive `prisma/manual-test/migrations/20261019000000_relational_runtime/migration.sql` are offline artifacts. Both must be reviewed/applied to the private empty schema before activation. They have not been executed by this change. Do not run them against the public production schema or through the default Prisma migration chain. Existing deployment/ACL approval requirements still apply.

In a browser, obtain a CSRF challenge and bootstrap with strict JSON `{}` using a live ADMIN Auth.js session. Synthetic automation may instead present the existing server-only `MANUAL_TEST_MOCK_BOOTSTRAP_SECRET` through `x-manual-test-bootstrap-secret`, together with the same challenge cookie, CSRF header, and exact Origin. Any Sec-Fetch header denies the automation credential. Never put that credential into a browser, URL, request body, public environment variable, or log.

Runs, fixtures, application groups/links/submissions, deposits, reservations, payments/items/refunds, sessions, grants, and idempotency receipts persist in relational private-schema tables. Each operation sets and verifies the transaction search path, locks its run, and reads/writes only that run. Challenges are one-use per process (tracked in memory; best-effort on serverless) and CSRF-verified, with a sliding-window limit of 120 issued challenges per rolling 60 seconds. Cleanup is authorized by the surviving OPERATOR session and deletes only closed-run rows in dependency order, retaining a retryable run tombstone. Database money columns are PostgreSQL INTEGER: values above 2147483647 are rejected rather than changed; zero-price synthetic classes remain supported.


Closing a run revokes reservation sessions and consumes grants but refreshes the OPERATOR session instead of issuing a separate cleanup credential. Cleanup requires the run to be CLOSED or CLEANED, needs no ACTIVE run or unexpired run, and is idempotent: re-running it on an already CLEANED run — whose session records were wiped by the first cleanup — succeeds with a no-op authorized by the HMAC-signed operator token plus the CSRF header. The retry path still verifies the token's HMAC signature and expiry, and the CSRF plaintext carried in the `x-manual-test-csrf` header is a second secret not derivable from the token.
