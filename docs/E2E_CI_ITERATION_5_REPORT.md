### Focused execution plan

`UX_SPECS` is an option of **`ux-cli.ts run` only**. It does not change plain Playwright collection or add workflow-dispatch inputs; the unchanged workflow continues running the complete suite. In a provisioned disposable CI harness with existing safety admission, seed and real auth completed, use:

```sh
UX_SPECS=integrated-ux-class-links,integrated-ux-guardian node --import tsx tests/e2e/support/ux-cli.ts run
UX_SPECS=integrated-ux-family-list node --import tsx tests/e2e/support/ux-cli.ts run
UX_SPECS=integrated-ux-class-links node --import tsx tests/e2e/support/ux-cli.ts run
UX_SPECS=integrated-ux-full-journey node --import tsx tests/e2e/support/ux-cli.ts run
```

These cover price, filter, class issuance, and P4 issuance/full journey respectively. Each project still needs an isolated fresh database/fixtures and the normal auth probe; focused selection does not bypass those requirements. Selected specs run in their original order. Every unselected spec remains visible as SKIPPED; a focused run is never evidence of a full 272-execution pass. Finish with `UX_SPECS` unset in the existing full matrix, retaining Ledger 8/8, Confirmation 7/7 per project and all 18 expected BLOCKED outcomes with unchanged admission.
